## 已知后置问题

跨组织重复 userNo：注册和导入检查按组织限定，但登录按全局编号查询。此问题在先前 MySQL 验收已复现。本轮按用户要求使用全局唯一合成编号，不修改后端规则，也不将该问题宣称为已修复。

建议后续独立处理 SysUserServiceImpl.java 中注册/导入重复检查，改为全局 user_no 检查，并在核对、清理现存重复后增加数据库唯一约束；在 SysUser.java 对应列声明与数据库保持一致。生产迁移前必须审核现存重复账号，不能直接对已有库执行强制索引变更。原验收 suggested-fixes.patch 与 migration SQL 仍保留在 acceptance_20261027_104708。

当前关闭新增组织、无密码重置/修改接口、无服务端分页、组织修改 DTO 无 status 均作为现有边界，前端没有虚构这些能力。日期严格解析和 ISO 日期 Excel 行级处理沿用最新后端修复。
